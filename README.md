# LC-time

浏览器时区扩展。弹窗展示所选时区的实时时间，下方可选择时区或用开关启用当前 IP 的时区。界面使用本地样式和文字标识，没有照片或外部字体依赖。

- 弹窗：24 小时制时间、秒数、日期、时区和 UTC 偏移。
- 工具栏电子钟：上行小时、下行分钟，切换设置立即更新，后台约每分钟刷新。浏览器休眠或节能调度可能推迟更新；重新打开弹窗时会立即刷新。
- 网页语言、默认字体和经纬度设置保留在“语言、字体与位置”折叠区。
- 设置自动保存并应用到已打开的受支持网页；弹窗会读取当前网页的实际时区，显示应用结果。选择浏览器默认时区可清除覆盖设置。

## 加载扩展

使用打包版：先解压 `LC-time.zip`，在扩展管理页开启开发者模式，点击“加载已解压的扩展程序”，选择解压后包含 `manifest.json` 的文件夹。当前版本号为 1.4.1，需要 Chrome / Chromium 125 或更新版本。

源码包含生成后的 `css/style.css`，可直接加载项目根目录：

1. 打开 `chrome://extensions/`。
2. 启用“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目目录。
4. 将 LC-time 固定到工具栏。

也可先运行以下命令，再加载 `build` 目录：

```sh
npm install
npm run build
```

修改 `tailwind.css` 后运行 `npm run build:css`，或使用 `npm run watch:css`。重新构建后，在扩展管理页点击重新加载。

## 1.4.1 连接恢复与诊断

修复旧“已暂停”记录阻止重新核验的情况：先检查实际连接所有权，仍持有连接时读取真实页面；用户明确点击恢复时，即使导航暂时没有 URL，也先清除旧暂停状态。异步写入按标签页排序，断开或关闭页面后，旧任务不能再覆盖新状态。

浏览器返回的 `canceled_by_user` 分类会记录在诊断中，但界面只显示“连接已断开”，不据此推断用户点过取消。主动关闭调试提示后，普通切换标签页不会反复重连；明确恢复、重新保存配置或主动刷新才会重试。

尚在导航的页面与初始空白文档显示“待核验”，加载完成后再读回当前文档。连接所有权检查不执行页面 JavaScript；时间和语言读回设置了执行时限，避免核验脚本无限等待。

弹窗底部“诊断”可复制扩展版本、浏览器版本、当前真实连接/时区/语言、目标地区、最近断开分类及时间、失败阶段和错误信息。复制不可用时显示可手动复制的文本。诊断不收集网页网址、IP、经纬度、Cookie 或浏览历史。

已在 Chrome for Testing 156 的**同一浏览器进程、两个用户配置**下验证同一 IP 地区、开发者工具开启、刷新、旧暂停状态恢复及诊断按钮。用户报告的“第二个配置自行断开”触发原因尚未复现；修复了可验证的恢复问题，不宣称已经确定所有断开原因。

## 1.4.0 多环境地区一致性

使用浏览器原生模拟接口同步主页面、同进程框架、跨进程框架、嵌套框架、Dedicated Worker、嵌套 Worker、Service Worker 与可发现的 SharedWorker。保持原生 `Date` / `Intl` 函数，不注入替代构造函数，也不改写 `Function.prototype.toString`。时区的夏令时及历史规则由浏览器自身处理。

对新建的相关子目标，先暂停启动、应用设置，再放行；异常时也会放行，5 秒保护计时器避免一直卡住网页。自动连接只初始化一次，避免导航时重复配置导致临时框架连接失效。切换地区时清理本扩展持有的旧语言覆盖，按当前配置顺序更新，防止共享渲染进程中的覆盖互相冲突。

共享 Worker 使用扩展允许的目标列表发现，约每 2 秒检查一次，只连接已管理网页／框架所属来源的普通网络 Worker。不会连接其他扩展的后台脚本。取消连接后不自动反复连接；显式重新启用设置或使用恢复按钮可重试。

弹窗分别显示“已应用 / 待核验 / 部分应用 / 未应用”。主页面通过而已发现的子环境失败时，会提示“部分应用”及原因。状态只代表实际读取到的环境，不代表整个浏览器指纹不可识别。

**范围与限制：**

- 首次新导航的早期脚本可能先于扩展连接执行。首次创建的 SharedWorker、独立运行且尚未关联网页的 Service Worker 存在发现窗口；不保证其第一条脚本或第一笔请求已覆盖。修改设置后，在目标页使用“刷新当前网页”再核验。
- 网站已保存的首访检测值、已创建的 `Intl` 格式化对象、账号语言或 Cookie 不会被追溯改写。恢复默认后也应刷新，以清除页面或同进程框架缓存的语言数组。
- 不改变实际公网 IP、操作系统、浏览器菜单语言、GPU、屏幕参数或已安装字体列表，不保证通过任何网站的全部指纹检测。手动经纬度仅覆盖网站获准读取的地理位置，不改变网络出口；只选择时区不会推断精确位置。
- Chrome 的调试提示仍由浏览器显示，扩展无法在自身界面内隐藏它。点击提示上的取消或 × 会断开连接。

验证环境为 macOS 上的 Chrome for Testing 156：美／日／中切换、八种执行环境、刷新后的首段脚本、请求语言、冬夏偏移、原生函数保持、双配置隔离、完整重启与恢复默认。上述测试不代表已覆盖所有网站和所有 Chrome 版本。可复现测试见 `TESTING.md`。

## 语言与字体联动

选择时区或开启 IP 时区时，自动选择对应的语言预设。网页 `navigator.language`、`navigator.languages`、请求头 `Accept-Language` 以及日期/数字地区格式一起切换。保留浏览器真实的 User-Agent 与客户端提示，不修改 Chrome 菜单或系统语言。网站可能优先使用账号、网址或 Cookie 中的语言偏好，这不是自动翻译功能。

IP 模式优先按查询结果的国家/地区选择语言；手动选择时区使用 IANA 国家/地区映射。多语言地区使用一个默认预设，不代表唯一语言；需要其他语言时，在手动配置中调整“网页语言与地区”。

默认字体会跟随语言，从已安装字体中选择。例如当前 Mac 测试环境：英语使用 Arial，日语使用 Hiragino Sans，简体中文使用 PingFang SC。其他系统可能选择不同字体。没有匹配字体时保留浏览器回退机制。此功能影响当前用户配置中的网页默认字体，不覆盖网站明确指定或下载的字体，不模拟字体列表。

“网页默认字体”选择“使用浏览器默认字体”可单独关闭字体联动；选择“使用浏览器默认时区”会恢复时区、语言、默认字体和位置。字体设置通过 Chrome 的扩展设置层管理，不覆盖用户原先的默认值。语言和字体跟随每个用户配置分别保存。

已实测美、日、中三组切换，核验网页语言、实际请求头、默认字体渲染、首段脚本、恢复默认，以及原始 User-Agent/客户端提示保持一致。更新增加 `fontSettings` 权限，需要在扩展管理页重新加载。

## 1.2.5 修复

修复连接被取消后，普通网页刷新仍无法恢复的问题。主动刷新网页会重新尝试应用保存的时区。扩展内的“恢复并刷新网页”会先恢复连接，再刷新，并核验刷新后的网页；刷新途中再次取消连接时不会强行恢复。

时钟展示目标时区的时间，右上角单独标明当前网页“已应用 / 未应用 / 待核验 / 不适用”。弹窗保持打开时也会更新连接状态。只有读回网页实际时区匹配后才显示“已应用”。

Chrome 顶部提示的“取消”和右侧“×”都会中断调试连接，并不是只隐藏提示。本版仍使用调试接口，仍会显示该提示。复现测试覆盖真实关闭提示、普通刷新恢复、开发者工具开启时通过扩展恢复，以及刷新后再次核验。

## 1.2.4 修复

修复保存设置时断开所有网页调试连接、导致开关开启但网页时区未生效的问题。保存和刷新会保留连接，刷新按钮会先确认设置成功应用再重载网页。连接冲突、权限限制或时区不一致会在弹窗内显示原因。

两个浏览器用户配置需要分别更新并启用扩展。更新时覆盖原来加载的扩展目录，然后在各自扩展管理页重新加载，确认版本为 1.4.1。部分网站会缓存首次加载时的检测值，更新后请在该网页打开扩展，点击“刷新当前网页”。首次新导航的早期脚本仍可能先于调试连接执行。

验证：`npm test` 运行连接管理回归测试；已使用两个独立测试配置、四个网页检查 IP 开关、重复保存、刷新、恢复默认与连接冲突。

## 工作方式

沿用原项目的浏览器调试接口实现时区、语言区域及地理位置覆盖。浏览器可能显示调试提示，部分内部页面不支持覆盖。

“使用当前 IP 时区”沿用原有的 IP 查询服务，仅在开启开关时查询当前网络出口；关闭后恢复之前的配置，失败时保留已有配置。此功能不会改变 IP 地址。

权限：`storage` 保存配置；`webNavigation` 监听网页导航；`debugger` 应用覆盖设置；`alarms` 在后台定期刷新电子钟图标；`fontSettings` 读取已安装字体并管理当前用户配置的网页默认字体。
